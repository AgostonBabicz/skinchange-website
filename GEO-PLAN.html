Overview

Executive Summary

This document is a structured Generative Engine Optimization (GEO) audit for SkinChange.AI ApS. GEO is the discipline of optimizing web content specifically for how AI systems — including ChatGPT, Google AI Overviews, Perplexity, and Bing Copilot — discover, understand, and reference your content in generated answers.

Based on a full technical audit of the Next.js website, the analysis covers all pages including the homepage, 19 disease-specific blog articles, the FAQ hub and sub-pages, the user guide, the about page, and the download/app page.

🔷 Current standing: SkinChange has a strong SEO foundation — proper hreflang, JSON-LD schemas, canonical URLs, and dual-language support are all in place. The primary gap is GEO-specific — missing schema types (HowTo, SpeakableSpecification, MedicalCode/ICD-11), thin FAQ answers, content depth, and infrastructure issues (plain-text fallbacks) that block AI visibility.

Critical Issues

Part 1 — Critical GEO Gaps

The items below are actively blocking AI visibility. They should be fixed before anything else.

1. Plain-Text Blog Fallbacks Destroying Schema

Critical

Problem: Every blog article generates two output files — index.html (full HTML + JSON-LD) and index.txt (raw text, zero schema). AI crawlers hitting the .txt URLs see an unstyled page with no structured data, no navigation, and no markup.

Example output in /dist/da/blog/acne/:

/dist/da/blog/acne/index.html ← ✅ Full HTML with schema /dist/da/blog/acne/index.txt ← ❌ Plain text, no schema, no HTML

Action: Delete all index.txt files from /dist/ and reconfigure the build pipeline to stop generating them. Run this to find all instances:

find /dist -name "index.txt" -delete

2. Missing HowTo Schema on Guide Page

Critical

The guide page (/da/guide/) teaches users how to use the SKIND app step-by-step. This is a prime target for HowTo rich results — a schema type that Google AI Overviews pulls from directly into featured answers.

Currently: No HowTo schema.

Required Addition — src/app/[lang]/guide/page.tsx

{ "@type": "HowTo", "name": "Sådan bruger du SKIND appen", "description": "Komplet guide til at oprette din undersøgelse i SKIND appen", "step": [ { "@type": "HowToStep", "name": "Download SKIND appen", "text": "Download SKIND fra App Store eller Google Play og opret en konto med MitID." }, { "@type": "HowToStep", "name": "Tag billeder af dit hudproblem", "text": " Brug appens kamera til at tage klare, godt oplyste billeder af det berørte område fra flere vinkler." }, { "@type": "HowToStep", "name": "Besvar spørgsmål om dine symptomer", "text": "Svar på simple spørgsmål om varighed, symptomer og sygehistorie for at hjælpe hudlægen." }, { "@type": "HowToStep", "name": "Modtag din diagnose", "text": "En certificeret Speciallæge i hudsygdomme gennemgår din sag og sender diagnose og behandlingsplan inden for 48 timer." } ] }

3. No SpeakableSpecification for AI Overviews

Critical

Google's AI Overviews on medical content require SpeakableSpecification — this marks which parts of a page are safe for AI to quote directly in search summaries. Currently missing from all Article and FAQPage schemas.

Required Addition — inside Article / FAQPage schema

"speech": { "@type": "SpeakableSpecification", "cssSelector": ["h1", "h2"] }

Add this to the homepage FAQPage schema and all 19 blog article schemas. For blog articles, use ["h1", "h2", ".prose h3"] as selectors.

4. Shallow Author Schema — E-E-A-T Gap

Critical

Peter Bjerring is referenced in schema as:

{ "@type": "Person", "@id": "https://www.skinchange.dk/#peter-bjerring", "name": "Peter Bjerring" // ❌ Missing: url, jobTitle, worksFor @id, alumniOf, knowsAbout, description }

AI engines use E-E-A-T (Experience, Expertise, Authoritativeness, Trustworthiness) as a core health content signal. The current Person schema has no verifiable credentials, no author page, and no way for an AI to confirm expertise.

Required actions:

  1. Create an author page at /da/about/peter-bjerring with full medical biography, credentials, and publications list
  2. Expand the Person schema on the About page to include full credentials, @id reference, and URL
  3. Add author links under every blog article that point to the author page
  4. Add Brian Vangsgaard as a second Person schema entry with his founder/CEO story

5. Sitemap Shows Identical lastmod for All Blog Posts

Critical

Every blog URL in sitemap.xml carries the build timestamp as its <lastmod>:

<lastmod>2026-03-26T10:43:40.616Z</lastmod> ← build time, not publish time

AI crawlers use lastmod as a freshness signal. Each article needs its actual datePublished and dateModified tracked and passed to the sitemap generator.

Action: Update src/app/sitemap.ts to pull datePublished and dateModified from each blog post's frontmatter or data file.

The MedicalOrganization address has country/region but no lat/lng. AI and map services need precise coordinates.

Note: Verify actual Vejle coordinates for Hindbærhaven 48, 7120 Vejle Ø.

10. Danish-Only Service Schema — Needs English Version

Your current Service schema describes the offering only in Danish. Add a separate English entry at /en/ with English-language description, service name, and areaServed: "DK".

Part 3 — Content & Semantic Improvements

11. FAQ Answers Too Short for AI Extraction

High

AI Overviews need 3–5 sentences minimum in natural-language Q&A format. Current FAQ answers are often 1 sentence.

❌ Current Answer
"Du modtager en diagnose og behandlingsplan inden for 48 timer."
✅ Expanded Answer
"Når du har uploadet dine billeder af hudproblemet og betalt de 298 kr., gennemgår en af vores certificerede Speciallæger i hudsygdomme din sag. Du modtager svar — inklusiv diagnose og en personlig behandlingsplan — inden for 48 timer. Hvis vi finder tegn på noget alvorligt, får du klar besked om næste skridt. Behandlingsplanen kan inkludere recept, som du kan hente på ethvert dansk apotek."

Action: Expand ALL FAQ acceptedAnswers across all FAQ sub-pages to 3–5 sentences each, using natural conversational Danish/English.

12. Blog Articles Need More Internal Linking

Currently only the acne article cross-links to eczema. Every article needs:

  • Related conditions section — link to 3–5 other relevant disease articles
  • Author byline with link — "Skrevet af Peter Bjerring →" linking to author page
  • CTA block — "Få en diagnose med SKIND →" linking to download
  • "Last updated" date visible in article body
  • Sidebar or bottom section linking to relevant FAQ sub-pages

13. Consistent Q&A Subheading Patterns

AI extracts answers from heading + paragraph pairs like ## Hvad er acne? + paragraph. Audit all 19 articles — any that don't follow this pattern should be updated to include descriptive <h2> subheadings above every Q&A section.

14. FAQ Schema on Non-FAQ Pages

Currently only the homepage has FAQPage schema. These pages should also carry FAQPage schema for relevant common questions:

PageFAQ Questions to Add
/da/download"Which devices?", "Is the app free?", "How do I install?"
/da/about"Who founded SKIND?", "Are dermatologists certified?", "Is my data safe?"
/da/contact"How do I reach support?", "What languages?", "Response time?"

15. Patient Testimonial Schema

The homepage has a testimonial section but no Review/AggregateRating schema. Add this to the homepage JSON-LD:

{ "@type": "Review", "reviewRating": { "@type": "Rating", "ratingValue": "5", "bestRating": "5" }, "author": { "@type": "Person", "name": "Jofrajen" }, "reviewBody": "Havde et stort modermærke på ryggen...", "itemReviewed": { "@id": "https://www.skinchange.dk/#service" } }
