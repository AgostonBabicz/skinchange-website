🔴 Critical Issues
Critical #1 OG image /og-image.jpg returns 404 — social sharing is broken
SEO +8GEO +5
The OG image referenced in all pages (https://www.skinchange.dk/og-image.jpg) does not exist — returns 404. Every share on Facebook, LinkedIn, Twitter/X, WhatsApp, and iMessage shows a broken/blank preview. This kills click-through rates from social and reduces AI crawler confidence in content quality. Fix: create a 1200×630px branded image and upload it to /public/og-image.jpg.
Critical #2 Blog articles + FAQ sub-pages missing from sitemap (30+ missing URLs)
SEO +7GEO +4
The sitemap.xml contains only 16 URLs. Missing: 8 blog articles × 2 languages (/da/blog/acne, /en/blog/rosacea, etc.), /da/blog + /en/blog index, and all 6 FAQ category pages (/da/faq/how-it-works, /da/faq/diseases, etc.) — totalling 30+ uncovered URLs. Google cannot guarantee discovery and indexing of this content without sitemap entries. Fix: extend sitemap.ts to include all blog slugs and FAQ category slugs.
Critical #3 Google Search Console not verified — placeholder code in production
SEO +5
The meta tag google-site-verification is literally set to "your-google-verification-code" — a placeholder that was never replaced. Without GSC verified, there is zero insight into crawl errors, indexing status, keyword performance, Core Web Vitals from field data, or manual penalties. This is foundational. Fix: create a GSC property, get the real verification code, and update layout.tsx.
Critical #4 Duplicate + conflicting structured data — fake review count (15,000 vs 100+ actual)
SEO +5GEO +5
layout.tsx injects a MedicalOrganization schema AND page.tsx injects a separate MedicalBusiness schema for the same entity — two conflicting @types. Additionally, the MedicalBusiness schema claims aggregateRating.reviewCount: 15000 while the live stats section shows "100+ cases." Google's Rich Result guidelines explicitly flag fabricated review counts as a manual penalty risk. Fix: consolidate to one schema block, remove or correct the fake review count.
Critical #5 hreflang not in <head> — only in sitemap (weakest signal)
SEO +4
The rendered HTML <head> contains no <link rel="alternate" hreflang="..."> tags. While the sitemap.xml includes xhtml:link alternates, Google recommends implementing hreflang in all three places (HTML head, HTTP headers, sitemap). Relying solely on sitemap is the weakest method and misses the in-page signal entirely. Fix: ensure the Next.js metadata alternates.languages configuration correctly renders to <link> tags in the HTML head.
🟠 Significant Issues
Significant #6 No robots.txt accessible — 301 redirect loop on skinchange.dk/robots.txt
SEO +4GEO +2
Accessing skinchange.dk/robots.txt returns a 301 redirect with no proper robots.txt served. Without it, crawlers have no guidance on which paths to crawl or avoid, and there's no Sitemap declaration pointing crawlers to sitemap.xml. Fix: add a public/robots.txt file with proper Sitemap reference and any necessary Disallow rules.
Significant #7 Blog article authors attributed to Organization instead of Person (E-E-A-T)
SEO +3GEO +5
All blog article schemas use author.@type: "Organization" (SkinChange.AI). Google's E-E-A-T guidelines for medical content strongly favour named medical professionals as article authors. Peter Bjerring's credentials (300+ publications, adjunct professor, specialist) are already in the Physician schema — they should be cross-referenced as the article author. Fix: update Article schemas to author.@type: "Person" with @id referencing the Physician entity.
Significant #8 Missing canonical URL on About page and Blog index page
SEO +4
The About page (about/page.tsx) and Blog index (blog/page.tsx) have no alternates.canonical in their metadata — inconsistent with the rest of the site. Without canonical tags, Google may index multiple versions or fail to consolidate link equity. Fix: add canonical + alternates to both pages' generateMetadata functions.
Significant #9 Stats section shows English labels on Danish page
SEO +2
On the /da/ homepage, the Stats section renders: "Cases handled", "Hour diagnosis", "Certified doctors", "Reviews" — all in English. This is a localisation failure that hurts Danish language relevance signals and user trust. Fix: connect Stats component labels to the i18n translation system (stats keys already exist in i18n.ts but aren't being used).
Significant #10 Invalid telephone placeholder in MedicalBusiness structured data
SEO +2GEO +1
"telephone": "+45-XXX-XXXX" is a hardcoded placeholder in the schema. Invalid/fictional contact data in structured data can cause Google to distrust the entire schema block and withhold rich results. Fix: either remove the telephone field or replace it with the real contact number.
Significant #11 Blog article images hosted on Unsplash (external dependency)
SEO +2
Article hero images are loaded from images.unsplash.com — a third-party CDN. This creates: a dependency on Unsplash uptime, potential future 404s, inability to set descriptive filenames (skin-condition-acne-treatment.jpg), and loss of image SEO value. Fix: download and self-host article images in /public/blog/ with SEO-optimised filenames and proper alt text.
🔵 GEO-Specific Issues (AI & LLM Visibility)
GEO #12 No MedicalCondition schema on disease blog/FAQ pages
GEO +5
Blog articles about acne, rosacea, psoriasis etc. use generic Article schema but don't implement schema.org/MedicalCondition. LLMs and AI search engines (Google SGE, Perplexity, Bing Copilot) use MedicalCondition entities to build structured knowledge graphs about diseases. Adding these entities directly links SKIND's content to high-authority disease concepts. Fix: add MedicalCondition JSON-LD to each condition blog/FAQ page.
GEO #13 No speakable schema on FAQ pages
GEO +4
AI assistants (Google SGE, Siri, Alexa, Gemini) use schema.org/Speakable to identify the most directly answerable content snippets on a page. Medical FAQ pages are prime candidates — short, authoritative Q&A pairs about conditions, pricing, and how the service works. Without speakable markup, AI systems have no explicit guidance on which content to surface as answers. Fix: add Speakable schema to FAQ category pages pointing to the accordion question/answer blocks.
GEO #14 Patient testimonials have no Review / AggregateRating schema
SEO +1GEO +3
The homepage FeedbackSection has real patient quotes (e.g., Jofrajen's mole story) but zero structured data. Review schema with real ratings enables Google star rich results, increases AI confidence in the service's trustworthiness, and directly supports E-E-A-T. Fix: add Review + AggregateRating schema to the feedback section using actual verified review data.
GEO #15 Missing x-default hreflang
SEO +1GEO +1
Neither the sitemap nor the HTML head includes an x-default hreflang entry (hreflang="x-default"). This tag tells search engines which version to serve to users whose language isn't matched — critical for a service targeting both Danish and international English speakers. Fix: add x-default pointing to /da (or a redirect landing page) in both sitemap.ts and the layout metadata.
